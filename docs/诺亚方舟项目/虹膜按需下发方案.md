# 虹膜数据按需下发 — 本地加密存储 + 临时上传

## Context

**问题**：虹膜设备里存了所有人的数据，任何人站在设备前都能识别，影响使用效果。

**目标**：虹膜设备平时保持锁定、不保留人员数据。仅在用户身份编码验证通过后、需要虹膜认证时，临时上传该人员的虹膜数据到设备，识别完成后删除，保证识别过程中设备上只有一条数据。

---

## 完整流程

### 阶段一：IAMS 下发虹膜凭证（passport-add）

1. 正常上传到虹膜设备（**设备已锁定** → memberSave → 解锁），使用 `http.request` 独立 TCP 连接（参考 `test-iris-upload`），**不需要等待8秒**
2. **上传成功** → 将完整 payload（memberSave 的 JSON 对象，包含 staffNum/memberName/irisLeftImage/irisRightImage 等）用 AES 加密存到 `data/iris_data/<credentialId>.json.enc` → 数据库凭证表 `iris_data_path` 字段记录文件路径 → 调用 `/memberDelete` 从设备删除该人员数据 → 返回 IAMS 成功
3. **上传失败** → 不存文件不删设备 → 照常返回 IAMS 失败

### 阶段二：用户输入身份编码 → 验证通过 → 进入虹膜认证步骤

1. 前端调 `/api/device/iris/preload`（入参：credentialId）
2. 后端查凭证 `iris_data_path` → 读取加密文件 → AES 解密 → **设备已处于锁定状态**，直接 memberSave 上传 → 解锁 → 开始识别
3. 前端收到 preload 成功 → 启动虹膜轮询

### 阶段三：虹膜认证完成

- **成功** → 前端调 `/api/device/iris/cleanup` 从设备删除当前人员数据 + 重新锁定
- **超时/失败** → 前端调 `/api/device/iris/cleanup` 从设备删除当前人员数据 + 重新锁定

### 兜底：回到首页/编码输入页面时

- 前端调 `/api/device/iris/cleanup`，确保设备上没有任何残留数据（万无一失）

### 删除场景

- IAMS 下发 passport-del → 删除数据库凭证 → 同时删除本地加密文件（设备上已无数据，无需调用删除接口）

## 修改清单

### 1. 数据库迁移

**`lib/database.ts`** — `initTables` 中新增：
```typescript
try {
  await database.execute(`ALTER TABLE credentials ADD COLUMN iris_data_path TEXT`);
} catch { /* 列已存在 */ }
```

### 2. 凭证模型扩展

**`lib/db-credentials.ts`**：
- `Credential` 接口新增 `iris_data_path: string | null`
- `upsertCredential` 参数和 SQL 新增 `iris_data_path` 字段
- `LIGHT_COLUMNS` 新增 `iris_data_path`
- `rowToCredential` 新增映射

### 3. 虹膜数据加密存储模块（新文件）

**`lib/iris-data.ts`**：
```
目录：data/iris_data/
文件名：<credentialId>.json.enc
加密：aesEncrypt(JSON.stringify(data))  // 复用 lib/crypto.ts 的 AES/ECB 密钥
```
- `saveIrisData(credentialId, payload)` → 确保目录存在 → 加密 → 写文件 → 返回相对路径
- `loadIrisData(credentialId)` → 读文件 → aesDecrypt → 返回 payload 对象
- `deleteIrisData(credentialId)` → 删除文件（文件不存在不报错）

### 4. 虹膜设备通信重构

**`lib/device-sync.ts`**：
- 新增 `httpRequest(endpoint, path, body?)` 函数（参考 `test-iris-upload/route.ts`，使用 Node.js `http.request` 创建独立 TCP 连接，避免 fetch keep-alive 问题）
- 修改 `setIrisDeviceSaveState` → 内部改用 `httpRequest`
- 修改 `syncToIrisDeviceWithoutLock` → 内部改用 `httpRequest`
- 修改 `deleteFromIrisDevice` → 内部改用 `httpRequest`
- 新增 `uploadIrisToDevice(endpoint, payload, skipBmpConversion?)` → 转换 BMP → 调用 `memberSave` → 返回结果（不含锁定/解锁，由调用方控制）

### 5. handlePassportAdd 虹膜分支修改

**`lib/device-sync.ts`** `handlePassportAdd` 虹膜分支改为：
1. `syncToIrisDevice`（正常首次上传流程，含锁定/等待/解锁）
2. 上传成功后：
   a. `saveIrisData(credentialId, payload)` 存储加密文件
   b. `upsertCredential` 时存储 `iris_data_path`，清除 `iris_left_image`/`iris_right_image`（大字段不再入库）
   c. `deleteFromIrisDevice` 从设备删除该人员数据
3. 上传失败：不执行步骤 2，原样返回失败

### 6. handlePassportDelete 虹膜分支修改

**`lib/device-sync.ts`** `handlePassportDelete` 虹膜分支改为：
1. 删除数据库凭证
2. `deleteIrisData` 删除本地加密文件
3. **不再调用 `deleteFromIrisDevice`**（设备上已无数据）

### 7. 新增 API 路由

**`app/api/device/iris/preload/route.ts`**（新）：
- 入参：`credentialId`
- 流程：查凭证 → 读 `iris_data_path` → `loadIrisData` → `getDeviceConfigs` 找虹膜设备 → **设备已锁定，直接 memberSave 上传** → 解锁
- 返回：`{ success, errorCode?, errorInfo? }`

**`app/api/device/iris/cleanup/route.ts`**（新）：
- 入参：`credentialId`
- 流程：查虹膜设备 endpoint → `deleteFromIrisDevice` 删除当前人员数据 → `setIrisDeviceSaveState(endpoint, 1)` 重新锁定
- 返回：`{ success }`

### 8. 前端组合认证页面修改

**`app/kiosk/combined/page.tsx`**：
- 虹膜步骤 `useEffect`：进入 `currentStep === 'iris'` 且未完成时，先调 `/api/device/iris/preload`，成功后再 `startIrisPolling()`
- `startIrisPolling` 超时/错误回调：调 `/api/device/iris/cleanup` 删除数据+锁定
- 认证成功后（`handleBiometricComplete`）：调 `/api/device/iris/cleanup` 删除数据+锁定
- 跳转到首页/编码输入页面时（`router.push('/kiosk')` 前或后）：调 `/api/device/iris/cleanup` 兜底清理

| 函数 | 文件 | 用途 |
|------|------|------|
| `aesEncrypt` / `aesDecrypt` | `lib/crypto.ts` | 虹膜数据加解密 |

| `syncToIrisDevice` | `lib/device-sync.ts` | passport-add 时首次上传（含锁定） |

## 验证

1. **passport-add**：上传成功 → 检查 `data/iris_data/` 下生成了 `.json.enc` 文件 → 设备上没有该人员数据
2. **passport-del**：删除后 → 数据库凭证和加密文件都被清理
3. **认证流程**：输入编码 → 虹膜步骤自动 preload → 识别成功/超时 → 设备删除数据+重新锁定
4. **兜底清理**：模拟前端崩溃（不 call cleanup）→ 回到首页时自动兜底清理
5. **凭证管理列表页**：虹膜凭证的 `iris_data_path` 字段正确显示
